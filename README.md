# Менеджер задач

Одностраничное веб-приложение для учёта задач: интерфейс на русском языке, разметка, стили и логика собраны в одном файле **`index.html`**. Данные в браузере: массивы `tasks` и `assignees` **автоматически сохраняются** в `localStorage` при изменениях и подставляются при следующем открытии страницы (в пределах того же браузера и источника страницы). Очистка данных сайта в настройках браузера удалит и это хранилище.

## Как открыть

Откройте файл `index.html` в браузере (двойной щелчок или через меню «Открыть файл»). Для корректной загрузки шрифтов и иконок нужен доступ в интернет (CDN Google Fonts и Font Awesome).

## Технологии

- HTML5, CSS (в т.ч. переменные, адаптивная вёрстка), JavaScript без сборки и фреймворков.
- Шрифт **Inter**, иконки **Font Awesome 6**.

## Модель данных задачи

Каждая задача содержит:

| Поле | Описание |
|------|----------|
| `id` | Уникальный числовой идентификатор |
| `title` | Название |
| `status` | `todo` — «Новая задача», `in-progress` — «В работе», `done` — «Готово» |
| `priority` | `high` / `medium` / `low` — высокий, средний, низкий приоритет |
| `dueDate` | Срок в формате `ГГГГ-ММ-ДД` |
| `assignee` | Имя ответственного из общего списка исполнителей |
| `attachments` | Массив вложений: `id`, `name`, `mimeType`, `dataUrl` (файл в виде data URL) |

## Режимы отображения

В шапке переключатель **Канбан** · **Таблица** · **Список** (рядом — выбор **темы** оформления):

- **Канбан** — три колонки по статусам, карточки с приоритетом, сроком и ответственным; внутри колонки сортировка по приоритету (выше — важнее).
- **Таблица** — строки с теми же полями, удобно для обзора и сортировки глазами.
- **Список** — компактный вертикальный список.
- На кнопках режимов показывается **число задач** с учётом текущих фильтров (одинаковое для всех трёх — это размер отфильтрованного набора).

## Тема и подсветка срока

- **Тема:** в шапке список **«Как в системе»** / **«Светлая»** / **«Тёмная»**; выбор сохраняется в `localStorage` под ключом `html_task.v1.theme`. Режим «как в системе» следует `prefers-color-scheme`, при смене настроек ОС интерфейс обновляется автоматически.
- **Срок сегодня** (`dueDate` совпадает с текущей датой): на канбане **красная** рамка карточки и **красная** дата; в таблице и списке — акцент на строке/дате; в форме задачи поле срока подсвечивается **красным**. Для любой другой даты дата **не** окрашивается в красный.
- **Срок завтра:** **жёлтая** (янтарная) рамка карточки и такая же дата — цвета подобраны для читаемости в **светлой** теме; в тёмной теме оттенки светлее.

## Фильтры

Панель фильтров позволяет сузить задачи по:

- статусу;
- приоритету;
- ответственному;
- текстовому поиску по названию.

Кнопка сброса очищает все фильтры. Селекты статуса и приоритета подсвечиваются цветом выбранного значения.

## Работа с задачами

- **«Новая задача»** — открывает модальное окно создания.
- **Клик по карточке / строке / элементу списка** (кроме кнопки удаления и элементов вложений) — редактирование.
- В форме задачи: название, статус (радиокнопки), приоритет, срок, ответственный, вложения; кнопки «Создать» / «Сохранить» и «Отмена».

### Удаление задачи

Кнопка с иконкой корзины на карточке, в таблице и в списке. Перед удалением показывается **модальное окно подтверждения** (не системный `confirm`).

## Канбан: перетаскивание

Карточки можно перетаскивать между колонками (**drag-and-drop**); статус задачи обновляется после отпускания в новой колонке. Перетаскивание не начинается с кнопок удаления, заголовка карточки и кнопок вложений.

## Ответственные (под канбаном)

Блок **«Ответственные»** под доской (в секции канбана); **по умолчанию свёрнут**, разверните заголовок, чтобы открыть содержимое:

- список исполнителей с возможностью **добавить** имя и **удалить** (нельзя удалить последнего; перед удалением — модальное подтверждение);
- при удалении исполнителя его задачи переназначаются на оставшегося в списке;
- списки в фильтре «Ответственный» и в форме задачи синхронизируются со списком исполнителей;
- для каждого ответственного отображается статистика:
  - по **статусам**: у каждого статуса три **цветные цифры** (высокий / средний / низкий приоритет) — сколько задач в этом статусе с данным приоритетом;
  - отдельной строкой — **всего по приоритету** (подписи нейтральные, цветные только цифры).

## Вложения к задаче

- Типы файлов: **Excel** (`.xlsx`, `.xls`), **Word** (`.docx`, `.doc`), **PDF**, **текст** (`.txt`), до **8 МБ** на файл.
- Файлы читаются в браузере и хранятся как **data URL** внутри объекта задачи.
- В форме: список вложений с кнопкой сохранения на диск и удалением (удаление вложения — с подтверждением в модальном окне).
- На канбане и в таблице у задачи отображаются кнопки вложений: по клику файл **скачивается** через временный `Blob`-URL (открытие во вкладке браузера отключено намеренно).

## Модальные окна подтверждения удаления

Единое окно подтверждения используется для:

- удаления **задачи**;
- удаления **ответственного** из списка;
- удаления **вложения** в форме задачи.

Пока открыто подтверждение, закрытие формы задачи по **Escape** не срабатывает, пока не закрыто окно подтверждения.

## FAQ

### Сохраняются ли задачи после закрытия браузера?

Да, в пределах одного браузера и того же способа открытия страницы (тот же `origin`): массивы **`tasks`** и **`assignees`** записываются в **`localStorage`** после правок и читаются при загрузке `index.html`. Если в хранилище повреждённые или чужие данные, приложение оставит встроенные примеры для соответствующего ключа. Сброс к демо-данным можно сделать, удалив в инструментах разработчика ключи `html_task.v1.tasks` и `html_task.v1.assignees` (или очистив сайт-данные для файла/сайта).

### Нужен ли сервер или Node.js?

Нет. Достаточно открыть `index.html` локально. Нужен только интернет для шрифтов и иконок с CDN.

### Почему вложение не открывается сразу в Word или Excel в браузере?

Браузер ограничивает запуск внешних программ. Реализовано **сохранение файла на диск** (часто в папку «Загрузки»); дальше файл можно открыть в нужной программе вручную.

### Удалил вложение в форме, но на карточке оно ещё видно

Изменения вложений попадают в задачу только после нажатия **«Сохранить»** / **«Создать»** в форме. До этого список на карточке соответствует последнему сохранённому состоянию.

### Можно ли удалить последнего ответственного?

Нет. В системе должен остаться хотя бы один исполнитель в списке; при одном человеке кнопка удаления покажет предупреждение.

### Что означают три цветные цифры рядом с «Новая задача», «В работе», «Готово» у ответственного?

Порядок цифр: **высокий** → **средний** → **низкий** приоритет. Каждая цифра показывает, сколько задач этого исполнителя в данном статусе имеет соответствующий приоритет. Подсказка при наведении на группу цифр дублирует порядок.

### Почему блок «Ответственные» не виден в режиме «Таблица» или «Список»?

Он расположен в секции канбана. Переключитесь на **Канбан**, чтобы увидеть список исполнителей и статистику.

### Фильтры влияют на цифры у ответственных?

Нет. Счётчики считаются по **всем** задачам в массиве `tasks`, а не по отфильтрованному списку. Фильтры меняют только отображение канбана, таблицы и списка.

### Не переносится карточка канбана

Убедитесь, что перетаскивание начато с «тела» карточки, а не с кнопки удаления, заголовка-ссылки или кнопки вложения — для этих элементов старт перетаскивания отключён.

### Как изменить начальные задачи или список ответственных?

В файле `index.html` внутри тега `<script>` отредактируйте массивы `tasks` и при необходимости начальный массив `assignees`.

## Ограничения

- Нет сервера и синхронизации между устройствами: данные только в **`localStorage`** этого браузера; при превышении квоты сохранение может не сработать (часто из‑за больших вложений в **data URL**).
- Большое количество тяжёлых вложений увеличивает объём страницы в памяти и размер записи в `localStorage`.

## Идеи для доработки

- **Синхронизация и аккаунты:** REST/GraphQL API, авторизация пользователя, облачное хранилище вместо только `localStorage`.
- **Резервные копии:** экспорт данных в JSON (скачивание файла) и импорт с валидацией схемы, чтобы переносить доски между браузерами и устройствами.
- **Напоминания:** уведомления браузера (`Notification API`) или локальный список «сегодня / на этой неделе» по полю `dueDate`.
- **Вложения:** загрузка на сервер вместо data URL, лимиты и антивирусная проверка на бэкенде; для чистого фронта — сжатие или хранение только метаданных + ссылка на облако.
- **Канбан:** настраиваемые колонки, WIP-лимиты, комментарии к карточке, история изменений статуса.
- **Качество кода:** вынести логику в отдельные `.js` / `.css` файлы, добавить сборку (Vite), тесты и CI на GitHub Actions.

---

При изменении логики данных правьте массив `tasks`, при необходимости — начальный массив `assignees` внутри `<script>` в `index.html`. Эти значения подставляются при **первом** открытии и когда данные в `localStorage` отсутствуют или не проходят проверку.
